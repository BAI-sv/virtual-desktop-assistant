## 这是什么

虚拟桌面助手 是**一个外壳**。它把三件事拼在一起：

| 层 | 是什么 | 谁提供 |
|---|---|---|
| **内核** | 一个完整的编码智能体（能读写文件、跑命令、调工具、多轮对话） | **DSH（可选）或 fairy_host 本地内核** |
| **外形** | 桌面悬浮球（呼吸/漂浮/眨眼/说话抖动） | 虚拟桌面助手（本仓库） |
| **语音** | 唤醒词 + 音色克隆合成 + 音乐让位 | 虚拟桌面助手（本仓库） |

**为什么这么分？** 因为"聪明的内核"和"好看的脸"是两件完全不同的事，
把它们耦在一起，改任何一边都得动全部。分开之后：

- 内核可以换（DSH / 别的智能体），脸不用改；
- 脸可以改（球 / 别的形象），内核不用动；
- 语音可以换（克隆 / Edge / 别的 TTS），前两者都不知道。

**这不是一个"AI 聊天软件"。** 它更像"给你的智能体装一个身体"。

## 核心特性

1. **内核 / 外形分离**
   内核可以是完整的 DSH 智能体（可选），单机模式用 `fairy_host.py` 本地内核；外形和声音是 Fairy。
   好处：换脸不改脑、换脑不改脸。所有交互都通过 HTTP 契约（`/api/fairy/*`）解耦。

2. **四层语音降级（每层都有存在理由）**

   | 层 | 触发条件 | 为什么要有它 |
   |---|---|---|
   | ① 预合成缓存 | 话术在缓存里 | 零延迟、不依赖合成服务在线 |
   | ② 实时克隆 | 缓存没命中、IndexTTS 在线 | 任意文本都能说 |
   | ③ 原声兜底 | 上一段见 `voice.md` | ★ **默认已停用**（见"与游戏素材解绑"） |
   | ④ Edge TTS | 前三层全失败 | 保命，宁可音色不对也不能哑巴 |

3. **实时音色克隆**
   用一段 3~10 秒的参考音 + IndexTTS，把**任意文本**用目标音色说出来（3~5 秒/句）。
   音色不是"预先录好的句子"，是"现场合成的声音"。

4. **保活看门狗**
   合成服务挂了没人管，声音就会掉成通用音色。
   `indextts_guard.py` 每 15 秒探一次，挂了自动拉起，**拉起后还会自动暖机**
   （冷启动第一次合成要 15~25 秒，暖机后降到 3~5 秒）。

5. **语音路由审计**
   `voice_audit.py` 从日志里统计"每一句话走了哪条路"，把"音色对不对"变成**可量化的数字**：
   ```
   GAME ORIGINAL : 0      CLONE cache : 12
   CLONE live    : 3      EDGE (.mp3) : 0   OK
   -> game-Fairy share = 100.0%  (of 15 played)
   ```

6. **唤醒方案：Sherpa-ONNX KWS（不用训练）**
   模型仅 3.3 MB，**改关键词不用重新训练**（写个文本文件即可）。
   实测：命中 10/12、误报 0/20、每块 1.36 ms（**73 倍实时**）、内存 124 MB。
   详见 [`wakeword.md`](wakeword.md)。

7. **音乐让位（ducking）而不是暂停**
   说话时把音乐**压低**到指定比例（P0 20% / P1 35% / P3 30%），说完平滑恢复。
    音频让位策略已**内置在代码里**（`media_duck.py` 的 PAUSE_HINTS、`volume_duck.py`），不用配置。

8. **一切都有日志与开关**
   每条播报路径都打 `语音=<路线>`；关键行为都有配置项；危险动作留备份（`*.bak_before_*`）。

## 架构

```
┌─────────────────────────────────────────────────────────────────┐
│  内核层：两种模式                                                 │
│    A. DSH（DeepSeek Harness）+ 插件 dsh-plugin-fairy（可选）       │
│    B. fairy_host 本地内核（19388，DSH 不在线时本地应答）          │
│    统一提供 HTTP 契约：/api/fairy/{say,reply,meta,task} + /fairy/ball  │
└───────────────┬─────────────────────────────┬───────────────────┘
                │ 球每 900ms 轮询 reply        │ 球请求 say 取音频
                ▼                             ▼
┌───────────────────────────────┐  ┌──────────────────────────────┐
│  外形层：fairy_ball.py         │  │  语音层                        │
│    悬浮球（128px，分层窗口）    │  │   indextts_server.py :9881    │
│    进度条面板 + 气泡            │─▶│     默认参考音 -> 克隆出 WAV   │
│    语音队列 _worker             │  │   indextts_guard.py（保活）    │
│    设备热插拔监听               │  │   voice_cache.py（预合成缓存） │
│    音乐让位（media/volume_duck）│  │   fairy_audio.py（默认输出设备）│
└───────────────┬───────────────┘  └──────────────────────────────┘
                │
                ▼
         声卡 -> 音箱 / 蓝牙耳机 / 显示器扬声器
```

**数据流（一句话）**：
`回复`（DSH 模式：DSH 插件推送；单机模式：fairy_host 本地产生）→
`/api/fairy/reply`（截断到 150 字）→
球轮询发现 `seq` 前进 → 推入语音队列 → `_worker` 四层降级选路线 →
合成/取缓存 → 让位音乐 → 播放 → 恢复音量。

详见 [`architecture.md`](architecture.md)。

## 环境要求

| 项 | 要求 | 备注 |
|---|---|---|
| 系统 | **Windows 10 1809+ / Windows 11** | 用了 Win32 分层窗口、Core Audio COM |
| Python | **3.12**（3.10/3.11 大概率也能跑） | 本仓库全部按 `py -3.12` 写 |
| 内核 | **DSH（可选）或 fairy_host 本地内核（单机模式）** | 不装 DSH 也能跑，球照常有回复 |
| 语音合成 | **IndexTTS**（可选但强烈建议） | 不装则退回 Edge 通用音色 |
| 唤醒 | **sherpa-onnx** + 3.3 MB 模型 | 可选 |
| 显卡 | 可选：AMD ROCm / NVIDIA CUDA / 纯 CPU | 纯 CPU 也能跑，只是慢 |
| 磁盘 | 视语音语料而定（自备） | 代码本身只有 ~1 MB |

**不需要**：任何云端账号、任何付费服务。（单机模式连 DSH 也不需要）

## 安装

### 1) 装 Python 依赖

```bat
py -3.12 -m pip install -r <FAIRY_ROOT>\requirements.txt
```

**说明**：`requirements.txt` 已按仓库全部 `.py` 的实际 `import` 重算（2026-10-10），
直接安装即可；分组（核心必装 / 功能可选 / 重依赖按需）见 [`config.md`](config.md)。

### 2) 部署 DSH 插件（可选，仅 DSH 模式需要）

把 `dsh-plugin-fairy/` 放进 DSH 的 profile 目录，重启 DSH。
**改插件源码后必须重启 DSH 才生效**（ESM 路径缓存）。
验证：`curl http://127.0.0.1:19387/api/fairy/meta` 有 JSON 返回即通。

### 3) 配置

```bat
py -3.12 <FAIRY_ROOT>\tools\fairy.py config
```
第一次跑会自动生成 `<FAIRY_ROOT>\fairy.json`。字段说明见 [`config.md`](config.md)。

### 4) 语音素材（**必须自备**）

见下一节。

## ★ 快速开始（5 分钟）

**目标：让桌面上出现一个球，并且能说话。**

```bat
:: 1) 体检（看缺什么）
py -3.12 <FAIRY_ROOT>\tools\fairy.py fastcheck

:: 2) 起语音合成（第一次要加载模型，约 35 秒）
py -3.12 <FAIRY_ROOT>\tools\fairy.py start tts

:: 3) 起球（门面）
py -3.12 <FAIRY_ROOT>\tools\fairy.py start ball

:: 4) 看状态（球在不在、我在干什么、余额多少）
py -3.12 <FAIRY_ROOT>\tools\fairy.py status

:: 5) 起保活守护（可选但建议：合成服务挂了自动拉起来）
py -3.12 <FAIRY_ROOT>\tools\fairy.py start guard
```

**验证语音真的走对了路线**：

```bat
py -3.12 <FAIRY_ROOT>\tools\voice_audit.py
```

输出里 **`EDGE (.mp3)` 应该是 0**，`CLONE cache / CLONE live` 应该有数字。
如果是 0/0（没有任何播放记录），说明球还没说过话 ——
在 DSH 里说句话，或用 `/api/fairy/push` 推一句（单机模式）试试。

**⚠️ 如果球"没声音"**：九成是默认音频输出设备被切走了。
`py -3.12 <FAIRY_ROOT>\tools\fairy_audio.py current` 看一眼，见 [`troubleshooting.md`](troubleshooting.md)。

## ⚠️ 外观素材也需要自备（球的脸不随仓库分发）

**本仓库同样不包含球的外观素材。** 原因与语音一样：**球的外观是米哈游的美术素材**，
官方指引允许**非商业个人使用**（须放法律声明），但**向他人分发素材本体不属于"个人使用"** ——
而仓库是面向公众的分发渠道。**所以 `assets/` 被排除是合规要求，不是缺陷。**

### ★ 开源版会发生什么（已核实代码，非推测）

```
fairy_ball.py  ASSETS = <FAIRY_ROOT>/assets/ball_128      <- 素材路径
fairy_ball.py  def load_frames(dim=0.82):
                   files = sorted(...png 文件...)
                   ...
               ★ 已内置占位回退：素材目录为空时使用【占位外观】（纯色圆），不崩
```

**（占位回退自 2026-10-09 起内置）**：

```
fairy_ball.py  load_frames() 现在有两层保护：
  · os.listdir 包了 try/except  -> 目录不存在也不抛
  · 逐帧 Image.open 也包 try    -> 坏帧跳过，不整体失败
  · 加载完若一帧都没有 -> 用【占位外观】（透明底 + 居中浅蓝圆）继续跑
  · 函数返回签名不变：(files, bright, dimmed)
实测三种情况（提供方实测）：
  真实素材目录   -> files=122  行为不变
  目录不存在     -> 打印警告 + 占位外观，不再崩
  目录存在但为空 -> 打印警告 + 占位外观，不再崩
```
**所以开源版 clone 下来【可以直接跑】** —— 球会显示成一个纯色圆，等你放自己的素材。

**想换成自己的外观**：把 `*.png` 放进 `<FAIRY_ROOT>\assets\ball_128\` 即可（规格见下表）。

### 你要自备什么

| 项 | 要求 |
|---|---|
| 目录 | `<FAIRY_ROOT>\assets\ball_128\`（**路径硬编码在 `fairy_ball.py` 第 47 行**，改路径要改代码） |
| 文件 | `*.png`，**每帧一张**，README 撰写时实测该目录有 **122 张** |
| 尺寸 | 建议 **128×128**（代码会自动 `resize` 到 `SIZE=128`，所以别的尺寸也能跑） |
| 格式 | PNG，**带 alpha 通道**（代码用 `convert("RGBA")`） |
| 命名 | 会被 `sorted()` 排序，所以**用零填充的序号**（如 `0001.png` … `0122.png`）最稳 |
| 另一份 | 代码里 `ASSETS` 只指向 `ball_128`；`assets/ball_96/` 是另一套尺寸（**当前代码未引用**） |

**简单替代方案**：自己画/生成 122 张（或几张循环也行）128×128 带透明通道的 PNG，
丢进那个目录即可。**帧数不强制 122，代码只是"有几张放几张"。**

## ⚠️ 语音语料需要自备

**本仓库不包含任何语音文件。** 原因：

1. **版权**：作者的语音素材来自某商业游戏，**不能随代码分发**；
2. **体积**：原始语料 600+ MB，不适合进 Git；
3. **反而更通用**：谁的音色谁自己配。

**你需要准备的只有一样东西：一段参考音。**

| 项 | 要求 |
|---|---|
| 时长 | **3~10 秒**（低于 3 秒会被 IndexTTS 直接拒绝） |
| 内容 | 单人、连续说话、**无背景音乐**、无他人声音 |
| 格式 | wav / mp3 皆可，采样率 16 kHz 以上 |
| 放置 | `<FAIRY_ROOT>\voice\index_voices\` 下，名字随意（如 `myvoice.wav`） |

**然后**：让合成服务用它 —— 在 `POST /tts` 的 `ref_audio` 字段指向它，
或在 `voice_index.json` 里登记。细节见 [`voice.md`](voice.md)。

**关于"和游戏素材解绑"**：项目里有一个总开关

```python
# fairy_ball.py 第 82 行 / fairy_ear.py 第 40 行
PLAY_GAME_ORIGINAL = False    # False = 不直接播原文件，一切走克隆
```

`False`（默认）时，**不会播放任何语料原文件**，全部走合成 ——
这样即使你手里有语料，发出去的包也不含它们。

## 常见问题（最常见的 5 条）

**Q1：球没声音，或者声音跑到蓝牙耳机里去了？**
用蓝牙麦克风会让 Windows 把**默认播放设备**也切到耳机（HFP 模式）。
```bat
py -3.12 <FAIRY_ROOT>\tools\fairy_audio.py current    :: 现在默认是哪台
py -3.12 <FAIRY_ROOT>\tools\fairy_audio.py list       :: 有哪些可选
py -3.12 <FAIRY_ROOT>\tools\fairy_audio.py set 扬声器   :: 切走
py -3.12 <FAIRY_ROOT>\tools\fairy_audio.py save       :: 记成"已知正常"
```

**Q2：说话变成"通用音色"了，不是 Fairy 的声音？**
合成服务（IndexTTS :9881）挂了，球降级到 Edge。
```bat
py -3.12 <FAIRY_ROOT>\tools\indextts_guard.py --status-json   :: 看它在不在
py -3.12 <FAIRY_ROOT>\tools\fairy.py start guard              :: 起保活守护
```

**Q3：重启后第一句话要等十几秒？**
冷启动（模型首次推理）。守护启动后会自动暖机；手动起的话先打一次 `/tts` 预热。

**Q4：球的日志文件是空的 / 球像个哑巴？**
球默认用 `pythonw.exe` 跑，`print()` 无处可去。
**用总管启动**才会把 stdout 落到日志：
```bat
py -3.12 <FAIRY_ROOT>\tools\fairy.py start ball
:: 日志 -> 见 fairy.py 里的 LOG 常量（默认 <WORKDIR>\logs\）
```

**Q5：喊唤醒词没反应？**
先确认**真的有程序在听**（`fairy_ear.py` 或 `fairy_wake_listen.py` 在跑），
再看 [`wakeword.md`](wakeword.md) 里的两个坑。
